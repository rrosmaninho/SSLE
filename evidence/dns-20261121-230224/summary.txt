==> PHASE 6 - Post-mortem
The hijack works by controlling the resolver the victim uses: pointed at
the rogue resolver, the bank name resolves to the clone and credentials
are captured. The defence is a protective resolver that scores the domain
BEFORE answering (risk = category + reports + domain age + DNSSEC + IP
reputation) and sinkholes the phishing name in the data path, so the
victim never reaches the clone. The SIEM turns each resolver decision into
an event: WARN, SINKHOLE, and a campaign alert on repeated hits.
Honest limits: reputation is evidence about the PAST, so a brand-new
domain with no history scores low (ADTree counter-defence C1); and the
defence only holds where the protective resolver is the one actually in
use - if the attacker controls resolv.conf, it can bypass it (C2 / gap
D3.5, pinned resolver configuration).
